# Основные игроки: данные и публикация

Общий блок расположен после обзора рынка в разборах ниш, на русском и английском. Ссылка на блок: `/ru/segment/<slug>#main-players`.

## Источник публичной версии

Первый локальный прототип использовал Astro. Перед массовой публикацией проверены [условия Astro](https://tryastro.app/terms/): раздел 18 запрещает распространение, перепродажу и коммерческое использование полученных через сервис данных. Поэтому прототипные снимки заменены независимым сбором из публичного Apple Search API. Баллы популярности и сложности Astro в публичную версию не входят.

Метаданные приложений, порядок ответа поиска, иконки и скриншоты получаются непосредственно из App Store. У каждого запроса записаны исходный URL и время получения. Изображения не генерируются; рядом со скриншотами размещён официальный значок App Store со ссылкой на приложение.

Источники: [Apple Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/), [параметры и ограничение частоты](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html), [значки App Store](https://developer.apple.com/app-store/marketing/guidelines/).

## Покрытие

Каталог содержит 72 категории. Для каждой подготовлено пять собственных поисковых запросов. Сейчас доступны 71 разбор: `astrology` уже возвращает 404 из-за отсутствующего архива отзывов. Сбор данных для неё не включает этот разбор и не обходит существующую проверку доступа к контенту.

Основной запрос задаёт выборку лидеров, до 20 результатов. Дополнительные четыре запроса сохраняют до 10 результатов каждый. Если Apple возвращает меньше приложений, число не дополняется. Дубли одного App Store ID удаляются с сохранением первоначальных позиций; пропуски позиций не перенумеровываются.

## Интерфейс

- **Топ выдачи** — приложения в порядке ответа поиска по выбранному ключу.
- **Лидеры ниши** — та же выборка основного запроса, отсортированная по числу оценок. Это не оценка долей рынка и не полный рейтинг всех приложений ниши.
- Карточки показывают иконку, название, оценки, скриншоты, позиции по ключам в этой выборке, App Store и наш разбор отзывов при точном совпадении ID.
- Первые пять карточек видны сразу. Остальные добавляются по пять; скриншоты прокручиваются горизонтально.
- При отсутствии скриншотов или числа оценок показана явная отметка, а не вымышленные данные. Неизвестное число оценок сортируется после настоящего нуля.

Порядок Apple Search API может отличаться от выдачи на устройстве. Ключи в карточке — только позиции среди пяти выбранных запросов, не полный набор ключей приложения или его закрытое ASO-поле. Число оценок не равно установкам, выручке или доле рынка.

## Реализация

- `src/data/marketPlayerQueries.json` — поисковые запросы по нишам.
- `src/data/marketPlayers/<slug>.json` — отдельный снимок каждой ниши.
- `src/lib/marketPlayers.server.ts` — загрузка только запрошенного снимка с проверкой slug по списку.
- `src/lib/marketPlayers.ts` — поиск строк, сортировка и обратная связь ключей с приложениями.
- `src/components/NicheMarketPlayers.tsx` — серверное соединение с архивом по App Store ID. Передаёт только публичные данные и ссылки; закрытые отзывы не загружаются.
- `src/components/MarketPlayersList.tsx` — общий интерфейс. При смене ниши выбранный запрос и размер списка сбрасываются.

Страница не обращается к Astro или Search API при открытии. Запрашиваются только изображения с CDN Apple. В браузер передаётся снимок текущей ниши, а не весь каталог. Общая сортировка идей и существующие права доступа не изменяются.

## Обновление и проверки

`npm run market-players:collect` собирает недостающие ниши, не превышая примерно 20 запросов в минуту. Данные каждой ниши сохраняются атомарно; после сбоя сбор можно продолжить. Для обновления: `npm run market-players:collect -- --refresh <slug>`.

`npm run test:market-players` проверяет полное покрытие каталога, источник, App Store ID, порядок выдачи, выборку лидеров, ссылки на изображения и отзывы, обе локали, пустые данные и отсутствие платных текстов в публичных свойствах. Режим `--collected-only` используется только во время сбора; CI требует полного покрытия.

После публикации workflow проверяет наличие блока и значка App Store на нескольких разных нишах в обеих локалях. Удалённые эксперименты `/aso` и `/workspace` по-прежнему должны возвращать 404.
