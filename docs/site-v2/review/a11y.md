# Site v2: accessibility review (report only)

Date: 2026-09-23. Scope: the shell (`src/site/shell/**`), UI primitives (`src/site/ui/**`), tokens and CSS (`src/site/styles/**`), and every feature that exists today (research, ideas, library/saved, settings, plus/paywall, auth, legal, landing, welcome). Method: code reading, a static scan of the SSR HTML from `http://localhost:3210` (landmarks, headings, names, alt text, `lang`, id references), and WCAG 2.x contrast computed from `tokens.css`. No screenshots were taken. Nothing in the repo was changed except this file.

**Files that were missing or changing during the review:**
- At the start, `src/site/features/landing/landing.css` did not exist. That broke compilation, and every page on :3210 returned 500 until it appeared (~00:01).
- `src/site/features/welcome/` did not exist at first. `WelcomeFlow.tsx`, `welcome.css` and `keys.ts` appeared at 00:02–00:03.
- `src/site/features/settings/` held only `settings.css` and `strings.ts` at first. `SettingsScreen.tsx`, `client.tsx`, `keys.ts` and `format.ts` appeared at 00:02.
- `/ru/privacy` and `/ru/welcome` returned 500 for a while (`CONTENT_ROOT is defined multiple times` in `src/site/i18n/server.ts`), then recovered.
- Everything below was reviewed as it stood at about 00:05. The owners are still writing these features, so line numbers may drift.
- Dialog, focus and motion behaviour was checked by reading the code. Nothing was exercised in a browser.

Severity: **blocker** = a flow cannot be completed with a keyboard or screen reader. **major** = WCAG 2.2 AA failure, or a serious barrier in a main flow. **minor** = best practice, a degraded experience, or a gap from the spec. There are no blockers.

## Major

### M1. Focus is lost after the "⋯" menu opens a sheet (note, export)
- **Web:** `src/site/ui/Menu.tsx:149-152` (`select` closes the menu, then calls `onSelect`). `src/site/ui/Sheet.tsx:92` saves `document.activeElement` as the opener.
- **Scenario:** Research reader: ⋯ → «Заметка к разбору» (`src/site/features/research/ArticleChrome.tsx:124-133`). Idea reader: ⋯ → «Записать мысль» or «Скачать документ» (`src/site/features/ideas/IdeaReader.tsx:57-63`).
- **Cause:**
  - The menu item that had focus is unmounted in the same commit that opens the sheet.
  - When the sheet effect runs, `document.activeElement` is `<body>`, so `<body>` becomes the opener.
  - On close, focus is "restored" to `<body>`. The next Tab starts again at the skip link. The native `<dialog>` restore target is `<body>` as well.
- **Source:** spec 05 §3.6 N (sheets restore to the opener); `ClarityReader.swift:195-204` (toolbar menus return to the toolbar). `SavedScreen.tsx:137-144` already works around this problem for its own menu.
- **Fix** (one place, covers every menu):
  ```tsx
  // Menu.tsx
  const select = () => {
    setOpen(false);
    triggerRef.current?.focus();   // the sheet records the ⋯ button as its opener
    item.onSelect?.();
  };
  ```
  After this, `SavedScreen.tsx`'s `returnTo` workaround (`:137-144`, `:330`) can stay or be removed.

### M2. Focus is lost after «Убрать из сохранённого» in Saved, and the removal is not announced
- **Web:** `src/site/features/library/SavedScreen.tsx:332-337`.
- **Cause:** The row, its ⋯ button and the menu item all unmount, so focus falls to `<body>`. The app removes the row without undo, so on the web the change is silent. The toolbar bookmark does announce with a toast (`library/components.tsx:42`); this menu path does not.
- **Source:** spec 02 §6 (row menu). `ClarityMy.swift:156-163` (VoiceOver moves to the next element when a row disappears).
- **Fix:**
  ```tsx
  onSelect: () => {
    const cur = li.current;
    const next = (cur?.nextElementSibling ?? cur?.previousElementSibling)
      ?.querySelector<HTMLElement>(".ia-lib-row__main");
    setSaved(row.kind, row.slug, false);
    toast(s.bookmarkRemoved);                       // same string as the toolbar toggle
    requestAnimationFrame(() =>
      (next?.isConnected ? next : document.getElementById("main"))?.focus({ preventScroll: false }));
  },
  ```

### M3. Focused elements scroll under sticky chrome (WCAG 2.4.11 Focus Not Obscured)
- **Web:**
  - ≥1024: the sticky `.ia-topnav` is 86 px (`site.css:1113-1123`: 12 + 62 + 12). On detail pages the sticky `.ia-toolbar` sits below it (`site.css:593-599`: `top: 86px`, 60 px tall), so 146 px of the top is covered.
  - <1024: the toolbar covers 60 px at the top of detail pages. The floating tab bar covers about 80 px at the bottom of tab roots (`site.css:1095-1102`). The landing sticky CTA covers about 76 px (`landing.css:1695-1711`).
  - No `scroll-padding` is set anywhere. Tab and Shift-Tab scroll the focused link to the viewport edge, underneath these bars.
  - The legal anchors use `scroll-margin-top: 88px` (`legal.css:84,150`), which is too small on desktop.
- **Source:** spec 05 §3.6 I/J (sticky top bar and toolbar, floating capsule). `.ia-rs-anchor` in `research.css:220-227` already uses the correct 86 + 60 + 12.
- **Fix:** add to `site.css` `@layer base`:
  ```css
  html { scroll-padding-top: 12px; }
  html:has(.ia-toolbar) { scroll-padding-top: calc(var(--ia-toolbar-h) + 12px); }
  @media (min-width: 1024px) {
    html { scroll-padding-top: 98px; }                                   /* 86 top nav + 12 */
    html:has(.ia-toolbar) { scroll-padding-top: calc(86px + var(--ia-toolbar-h) + 12px); }
  }
  @media (max-width: 1023.98px) {
    html:has(.ia-tabbar-dock) { scroll-padding-bottom: var(--ia-tabbar-reserve); }
    html:has(.ld-sticky[data-shown]) { scroll-padding-bottom: calc(80px + env(safe-area-inset-bottom)); }
  }
  ```
  Then set `scroll-margin-top` to 0 in `legal.css:84,150` and `research.css:220-227`. Scroll margin and scroll padding add up.

### M4. Error text in `--ia-error-system` fails contrast in light (3.26:1)
- **Web:**
  - `tokens.css:35` is `#ff3b30`.
  - It is used as text in `plus.css:177-183` (`.ia-plus__error`, 13 px) and `auth.css:204-206` (`.ia-auth__error`).
  - It is also used as an icon in `plus.css:343-345` (`.ia-checkout__icon--fail`, 2.86:1 on its tint).
- **Measured:** 3.26 on paper, 3.55 on surface, 3.46 on reading paper. AA requires 4.5.
- **Source:** spec 05 §1.1 (`--ia-error-system` = `.red`, `ClarityPaywall.swift:197`); spec 05 §1.3 says "all text pairs pass AA", but this pair was never measured. iOS itself switches to `#D70015` when Increase Contrast is on.
- **Fix:** `tokens.css:35` becomes `--ia-error-system: #d70015;`. That gives 4.94 on paper, 5.38 on surface, 4.58 on its 9 % tint, and 4.14 for the checkout icon. Dark `#ff453a` passes (5.50 on paper, 4.89 on surface). For the tinted auth notice, `#ff6961` in dark gives 5.23.

### M5. Telegram sign-in button: white on `#2AABEE` is 2.57:1
- **Web:** `auth.css:4` (`--ia-auth-tg: #2aabee`) and `auth.css:141-144` (`.ia-auth__method--tg { color: #fff }`). The hover state (88 % + black) is 3.28. This is the first sign-in method, in both the dialog and `/login`.
- **Source:** spec 05 §6.2 ("One accent… 44 px targets"); WCAG 1.4.3.
- **Fix:** `--ia-auth-tg: #0b6fb3;` gives white at 5.33:1 and hover at 6.49:1. The alternative is to keep `#2AABEE` with `color: #191a20` (6.74:1).

### M6. Error toast in dark: white on `--ia-danger` `#F4928C` is 2.25:1
- **Web:** `site.css:910-913`. Used by the sign-out failure toasts (`HeaderParts.tsx:99`, `settings/client.tsx:211`) and the auth notice toast (`SignInHost.tsx:80`).
- **Source:** spec 05 §1.1 (`--ia-danger`) and §4 item 10.
- **Fix:**
  ```css
  .ia-toast--error { background: var(--ia-danger); color: var(--ia-paper); }
  ```
  This gives 4.66 in light and 8.33 in dark.

### M7. Welcome carousels autoplay with no pause, previous or next controls (WCAG 2.2.2)
- **Web:** `src/site/features/welcome/WelcomeFlow.tsx:59-143`.
  - The step 2 carousel advances every 7 s; step 3 every 6 s.
  - Autoplay pauses only on hover, focus or pointer-down. That gives touch and screen-reader users no way to stop it.
  - It is already off under reduced motion, which is good.
  - The landing carousel does this correctly (`landing/Carousel.tsx:125-154`: arrows, dots, a pause toggle, and `aria-live` off while running).
- **Source:** spec 05 §5.1 "Carousel autoplay" row ("pause on hover/focus/touch; provide prev/next and pause controls (WCAG 2.2.2)"); `ClarityWelcomeCarousel.swift:17,59-66`.
- **Fix:**
  - Reuse the landing pattern: a 44 px «Пауза» / «Продолжить» toggle under the carousel, plus prev/next buttons (`ChevronLeftIcon`/`ChevronRightIcon`, `ia-wel-back` style). Store `userPaused` in state and stop the interval while it is true.
  - Put `aria-live={running ? "off" : "polite"}` on the track.

## Minor

### m1. The bookmark toggle changes its label *and* sets `aria-pressed`
- **Web:** `library/components.tsx:37-46`. A screen reader hears "Убрать из сохранённого, toggle button, pressed", which reports the state twice with conflicting wording.
- **Source:** `ClarityReader.swift:805-806` (the app changes the label and exposes the state as a value); spec 01 §5.6.
- **Fix:** keep the name constant and let `aria-pressed` carry the state:
  ```tsx
  <IconButton label={t("Сохранить")} pressed={saved}
    title={saved ? t("Убрать из сохранённого") : t("Сохранить")} …>
  ```
  `title` is spread after `label` in `Toolbar.tsx:76-79`, so it overrides.

### m2. Tab bar: the current section is not exposed on inner pages
- **Web:** `shell/TabBar.tsx:43`. `aria-current="page"` is set only at the tab root. On `/segment/<slug>` the desktop capsule shows the active pill (`data-active`), but assistive tech gets nothing.
- **Source:** `ClarityFloatingTabBar.swift:68-69` (`.isSelected` trait); spec 05 §3.6 I.
- **Fix:** `aria-current={active ? (atRoot ? "page" : "true") : undefined}`.

### m3. The language trigger's accessible name does not contain its visible text (WCAG 2.5.3)
- **Web:** `shell/HeaderParts.tsx:57-62`. The visible text is "RU" (hidden from assistive tech); the name is "Язык: Русский".
- **Fix:** ``triggerLabel={`${locale.toUpperCase()} — ${label}: ${LOCALE_NAMES[locale]}`}``.

### m4. Account menu: the name and Plus status are unreachable
- **Web:** `ui/Menu.tsx:135-139` renders `type:"label"` as `role="presentation"` inside `role="menu"`, so screen readers skip it. The trigger's name is just «Аккаунт» (`HeaderParts.tsx:88-105`).
- **Fix:** `label={heading ? `${s.account}: ${heading}` : s.account}`. This names both the trigger and the menu. Keep the visual label row.

### m5. Focus rings are clipped inside horizontal scrollers
- **Web:**
  - `site.css:503-512`: `.ia-chips { overflow-x: auto }` makes `overflow-y` compute to auto. The 2 px + 2 px ring of the Saved filter chips is cut off at the top, the bottom, and the first chip's left edge.
  - The same happens to links inside `.ld-carousel__track` (`landing.css:~645-665`) and `.ia-wel-carousel`.
- **Source:** spec 05 §6.2 ("Focus = 2 px accent outline, 2 px offset").
- **Fix:** `.ia-chips { padding: 4px; margin: -4px; }`. For focusables inside the carousel tracks, use `outline-offset: -2px`.

### m6. Skip link: `<main>` draws a page-sized focus ring
- **Web:** `ChromeFrame.tsx:59-67` and `site.css:110-113`. `main#main[tabindex=-1]` matches `:focus-visible` after keyboard activation of the skip link.
- **Fix:** `.ia-main:focus { outline: none; }` (in `site.css`, next to `.ia-main`, line 1002). The skip link itself is correct: it is the first focusable element, has a localized label, becomes visible on focus, and targets an existing `#main`.

### m7. Touch targets under 44 px on touch screens
- **Source:** spec 05 §3.6 H ("Minimum hit target everywhere: 44 × 44", with `ClarityBackNavigation.swift:15`, `ClarityMy.swift:103` and `ClaritySettings.swift:189` as sources). All of these pass AA 2.5.8 (24 px). Below the project's 44 px rule:

| `site.css:1279-1284`, `:1303-1310` | 36 | footer links, footer languages |
| `site.css:970-972` `.ia-appstore-badge--sm` / md | 34 / 40 | settings row, paywall iPhone block, footer, promos |

| `site.css:468-479` `.ia-search__clear` | 32 | matches the app (`ClarityStyle.swift:141` is 32×32); optional |

**Fix:** under `@media (pointer: coarse)`, set `min-height: 44px` on the text controls above. For the badges, pad the button or link to 44 (`padding-block: calc((44px - var(--ia-badge-h)) / 2)`).

### m8. Catalog cards have no heading, and their link names are long
- **Web:** `research/CatalogCard.tsx:52` and `ideas/IdeaCard.tsx:91` render the title in a `<span>`. The catalogs expose only h1 (plus h2 «Скоро в новом формате»), so heading navigation cannot jump between the 35 topics or the 293 ideas. The link name is title + lock + summary (+ badge).
- **Source:** `ClarityCatalogs.swift:151-155` (label = title or «%1$@. Бесплатный разбор.», hint = summary / «%1$@ Полный разбор в Plus.»); `ClarityIdeaCard.swift:70-71`.
- **Fix:**
  - Research card: `<h2 className="ia-rs-card__title" id={titleId}>`, with `aria-labelledby={titleId + (free ? " " + badgeId : "")}` and `aria-describedby={summaryId + (locked ? " " + lockId : "")}` on the link.
  - Idea card: add a `titleAs` prop. Use h2 in the ideas catalog, h4 under observation h3s, and h3 under «Другие идеи категории» h2.

### m9. Live regions are created together with their text, so announcements are unreliable
- **Web:**
  - `app/(site)/site/[lang]/segment/page.tsx:74-78`: `<p role="status">Найдено: N</p>` exists only when `q` is not empty.
  - `ideas/ExportSheet.tsx:179-183`: «Документ сохранён».
  - `plus/CheckoutReturn.tsx:98`: the confirmed view.
- **Fix:**
  - Always render the status element (empty when there is nothing to say) and change only its text: `<p className="ia-rs-count" role="status">{query ? t("Найдено: %1$@", …) : ""}</p>`.
  - In the export sheet, keep one `sr-only` `role="status"` node and write «Скопировано» or «Документ сохранён» into it.
  - The ideas catalog already does this correctly (`IdeasCatalog.tsx:107-109`).

### m10. Export preview: `aria-label` on a generic `<div>`
- **Web:** `ideas/ExportSheet.tsx:221`. ARIA prohibits names on generic elements, so the name is dropped. The element is focusable (`tabIndex=0`).
- **Fix:** add `role="region"` (keep `aria-label={t("Предпросмотр документа")}`).

### m11. Idea footer actions are wrapped in `<nav>`
- **Web:** `ideas/IdeaReader.tsx:69`. Two of the three items are buttons that open dialogs, not navigation. It also repeats the ⋯ menu's name «Действия с идеей».
- **Source:** spec 02 §3.6; `ClarityReader.swift:543-564`.
- **Fix:** `<div className="ia-idea__actions" role="group" aria-label={t("Действия с идеей")}>`.

### m12. `ErrorView` wraps the whole page in `role="alert"`
- **Web:** `shell/StatusViews.tsx:37`. On render, the heading, the body and "Повторить" are all read out assertively.
- **Fix:** drop the wrapper's `role="alert"`. Instead, focus the `<h1 tabIndex={-1}>` on mount, or put `role="alert"` only on the `<p>`.

### m13. Star ratings: empty stars are nearly invisible, and one welcome slide says "black star"
- **Web:**
  - `research.css:408-410`: `.ia-rs-stars__off` is ink @ 20 %, 1.52 / 1.81:1.
  - `ideas.css:347-349`: `.is-off` is `--ia-line`, 1.30 / 1.57:1.
  - Both groups have a correct `role="img"` + `aria-label`, but sighted users cannot tell 3 of 5 from 5 of 5.
  - `welcome/WelcomeFlow.tsx:305` renders `<b>{rating} ★</b>`, read as "4 black star".
- **Fix:**
  - For empty stars, use an outline glyph in `--ia-secondary` (5.41 / 7.93:1): `☆` in `ResearchArticle.tsx:67-71`, and `fill="none" stroke="currentColor" strokeWidth={1.6}` in `IdeaArticle.tsx:106-113`.
  - Welcome: `<b role="img" aria-label={t(... "Оценка %1$@ из 5")}>` (same as `landing/parts.tsx:151`).

### m14. Reduced-motion and ambient-motion gaps
- **Web:**
  - `site.css:1416-1429` zeroes animations only. Transitions not driven by tokens still run: `landing.css:1707` (sticky CTA slides 320 ms) and `landing.css:566` (`.ld-idea:hover` translate).
  - The hero papers drift forever (`landing.css:366-372`, 6 s / 7 s). Welcome `.ia-wel-float` loops for 12 s. Neither pauses off-screen, and neither has a stop control (WCAG 2.2.2 applies to decorative motion longer than 5 s).
  - Under reduce, `.ia-spinner` freezes after 0.01 ms (`site.css:359-366` + `:1418-1422`). It still looks like a ring but no longer signals progress.
- **Source:** spec 05 §5.1 ("pause loops on `visibilityState === hidden` and when off-screen (IntersectionObserver)"); `ClarityStyle.swift:51`, `ClarityWelcomeContentPreview.swift:22`.
- **Fix:**
  - Wrap those two transitions in `@media (prefers-reduced-motion: no-preference)`.
  - Stop `ld-drift` after 2 iterations (`animation-iteration-count: 2`), or toggle `animation-play-state` with an IntersectionObserver.
  - `@media (prefers-reduced-motion: reduce) { .ia-spinner { animation-duration: 1.6s !important; animation-iteration-count: infinite !important; } }` (a slow spinner is essential motion).

### m15. Too many landmarks: every `<section aria-labelledby>` becomes a region
- **Web:** `research/ResearchArticle.tsx:168` (7–8 per article), `legal/components.tsx:100` (13 on `/offer`), `landing/parts.tsx:98` (13 on the landing page), `settings/SettingsScreen.tsx:88`.
- **Fix:** drop `aria-labelledby` from content sections; headings already give the structure. Keep it only for regions worth jumping to: `#main-players`, landing S1 and S12, settings groups if wanted.

### m16. Landing FAQ puts `<h3>` inside `<summary>`
- **Web:** `landing/LandingPage.tsx:593-597`. In VoiceOver and NVDA, `summary` is exposed as a button and flattens its children, so the questions disappear from heading navigation. (The server scan counts them because it reads the DOM.)
- **Fix:** use the APG accordion pattern instead: `<h3><button aria-expanded aria-controls>q</button></h3><div id hidden>a</div>`. Or accept the trade-off and remove the `<h3>`.

### m17. Focus after client-side navigation stays on `<body>`
- **Web:** `shell/RouteObserver.tsx:20-22`. Next's announcer reads `document.title`, but after a card click the next Tab starts at the skip link.
- **Fix** (optional): on a pathname change (not the first render, not a hash change), call `document.getElementById("main")?.focus({ preventScroll: true })`.

### m18. Focus is lost when a control removes itself
- **Web:** `shell/OpenInAppBanner.tsx:22-25` (dismiss) and `plus/PlusOffer.tsx:233-266` («Купить навсегда» → the method step replaces the button).
- **Fix:**
  - After dismiss, focus `#main`.
  - On `step === "method"`, focus the methods title: `<p id={methodTitleId} tabIndex={-1}>` + `ref.focus()`.

### m19. Closed dialogs reference ids that do not exist yet
- **Web:** `ui/Sheet.tsx:175`. While closed, `aria-labelledby` points at the title id, which is rendered only when open. The scan shows 1–4 dangling ids per page. Harmless in AT, but it fails validators.
- **Fix:** `aria-labelledby={open && title !== undefined ? titleId : undefined}`.
- **Verified OK:** native `showModal()` makes the rest of the page inert (a real focus trap). Escape works (both `cancel` and `keydown`). Focus returns to the opener except in M1. Back closes the sheet. Nested confirmation dialogs work, and «Продолжить редактирование» is focused first.

### m20. Toasts render below the top layer
- **Web:** `ui/Toast.tsx:43`. The host is a normal fixed `div` (z 80). A toast raised while a modal `<dialog>` is open is drawn under the backdrop and is inert (not announced). Today this almost never happens: `SignInHost.tsx:91-93` fires `toast(signedIn)` in the same commit that closes the dialog, and the close runs in an effect afterwards.
- **Fix:** give the host `popover="manual"` and call `showPopover()` when items exist, so it sits in the top layer above dialogs. Otherwise, defer that toast with `setTimeout(…, 0)`.

### m21. Windows High Contrast (forced colors): boundaries and selected state disappear
- **Web:** `site.css`. The search field, chips, tab pills, glass pills, `.ia-account-btn`, cards and menus draw their edges only with `box-shadow` or backgrounds, and `border: 0`. Both are removed in forced colors, and the selected tab or chip is shown by background alone.
- **Fix:**
  ```css
  @media (forced-colors: active) {
    .ia-search, .ia-chip, .ia-tab, .ia-glass-pill, .ia-icon-btn--circle, .ia-account-btn,
    .ia-btn--secondary, .ia-card, .ia-menu, dialog.ia-sheet { border: 1px solid CanvasText; }
    .ia-tab[aria-current="page"], .ia-tab[data-active], .ia-chip[aria-pressed="true"] { outline: 2px solid Highlight; }
  }
  ```

### m22. Category picker rows mark the selection with `aria-current="true"`
- **Web:** `ideas/IdeasCatalog.tsx:194-199`. This is a single choice from a set, and screen readers announce "current" poorly here.

### m23. Truncated text at 200 % zoom or narrow widths (WCAG 1.4.4, 1.4.10)

### m24. The App Store badge art is always English while its alt text is localized

### m25. A research cover's alt text repeats the h1 (ru, 32 launch topics)
